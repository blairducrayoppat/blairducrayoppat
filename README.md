# Blair DuCray-Oppat, AIGP

I spent years in data privacy, finishing as Manager of Data Privacy and Data Governance at a public company. A lot of that time went to two questions: what can reach the data, and what did it do once it got there. AI agents now put those questions to every company at once. On September 20, 2026, a training agent inside OpenAI's sandbox [reached an outside chatbot through the DNS resolver](https://alignment.openai.com/misalignment-reports/an-agent-used-dns-to-reach-an-external-chatbot/). The web proxy had blocked it, so it encoded its questions as domain lookups and read the answers back in DNS records. A monitor flagged it within about fifteen minutes; the run kept going for two and a half hours more, because it did not stop on its own. OpenAI's fix was two independent blocking layers, either of which would have been enough. I read that the way I've read incidents for years: not "was the model clever" but "what could it reach, and can we show what it did?" An agent does not go through the wall you built; it goes through the seam you assumed was too small to matter, and a detector that notices is not a boundary that holds. Luke Hinds put the underlying rule in one line in his [sandbox primer](https://nolabs.ai/blog/sandbox-primer): "a prompt-level rule can be argued with; a kernel cannot."

Those years convinced me that most AI tools are built so every query and every document passes through infrastructure the user doesn't control. Since November 2025 I've been building the alternative. **BlarAI** is a personal research project: a local, security-first AI system on one Windows laptop. I believe the laptop already on your desk can run useful AI privately, and that an AI agent acting on your machine should answer to controls you can check.

**How the controls are built**

- **Deterministic checks.** In the assistant, every tool call and fetch a model initiates is reduced to a canonical action and checked against deterministic rules.
- **Untrusted content is action-locked.** Outside content is datamarked when it comes in and action-locked: it can steer the model's words, but it cannot fire a non-exempt tool.
- **One network door in the runtime.** Exactly one module in the assistant runtime may import an HTTP client, enforced by an import scan. Optional web search goes out through that one deny-by-default door.
- **Hardware-rooted trust.** Non-exportable TPM 2.0 keys, signature-verified model manifests enforced fail-closed, and AES-256-GCM encryption at rest under a TPM-sealed key.
- **Tested off.** The standing rule is that a security control ships with a test that it blocks and a test that the probe fails when the control is off, so "secure" can be told apart from "the test can't reach it."

**Containing the coding agent (in progress).** BlarAI's coding agent runs as my own Windows account today. I'm moving it into a separate restricted account, so that Windows file permissions, not the agent's own settings, decide what it can read and write, and only my account can commit and merge. The code is public in [agentic-setup](https://github.com/blairducrayoppat/agentic-setup-public). Three pieces of it: once the coder has run, the dispatch never runs plain git in its worktree, so the [git arguments](https://github.com/blairducrayoppat/agentic-setup-public/blob/fe206ce127e4a9e5c751057b8c08ebece1e06d18/scripts/fleet-lib.ps1#L992) pin the git directory and work tree and turn off hooks and fsmonitor, after a [check](https://github.com/blairducrayoppat/agentic-setup-public/blob/fe206ce127e4a9e5c751057b8c08ebece1e06d18/scripts/fleet-lib.ps1#L1100) of the worktree's identity and a fingerprint of its git configuration; the worktree is [held open](https://github.com/blairducrayoppat/agentic-setup-public/blob/fe206ce127e4a9e5c751057b8c08ebece1e06d18/scripts/fleet-lib.ps1#L1047) so it cannot be swapped out under that check; and the coder's process tree runs inside a [job object](https://github.com/blairducrayoppat/agentic-setup-public/blob/fe206ce127e4a9e5c751057b8c08ebece1e06d18/scripts/coder-leg-queue.ps1#L797) created kill-on-close with no breakaway. The [design record](https://github.com/blairducrayoppat/agentic-setup-public/blob/fe206ce127e4a9e5c751057b8c08ebece1e06d18/docs/fused-leg-operator-uses.md) lists each operator-side use of a path the coder can write in the dispatch scripts, and names what it did not audit. [A separate AI agent's adversarial review](https://github.com/blairducrayoppat/agentic-setup-public/blob/fe206ce127e4a9e5c751057b8c08ebece1e06d18/docs/reviews/code-review-775-fused-leg-2026-10-05.md) is published with its findings; the first was that a forged result file was accepted as a real coder run, and that is fixed in the snapshot. This is an account boundary, not a kernel or VM boundary. It is not switched on yet, and blocking that account's outbound network traffic is still an open gap.

The project keeps its misses on the record: walked-back measurements, rejected designs, and defenses that failed their own tests and were parked rather than shipped ([lessons](https://github.com/blairducrayoppat/blarai-public/blob/main/LESSONS.md) · [build journal](https://github.com/blairducrayoppat/blarai-public/blob/main/BUILD_JOURNAL.md)).

### Open source

I contribute upstream to the tools I depend on: fixes, hardware testing and measurement from real workloads on Intel Lunar Lake (Arc 140V GPU, NPU), across OpenVINO, OpenVINO GenAI, the NPU compiler, Optimum Intel and OpenVINO Model Server.

- **Authored:** one merged fix, [openvino.genai#4082](https://github.com/openvinotoolkit/openvino.genai/pull/4082) (a structured-output crash at end-of-sequence under speculative decoding). Open work is mainly GPU mixture-of-experts offload, NPU quantization and Eagle3 speculative decoding; the full list is on GitHub: [pull requests](https://github.com/search?q=author%3Ablairducrayoppat&type=pullrequests), [issues](https://github.com/search?q=author%3Ablairducrayoppat&type=issues).
- **On others' work:** reproduced bugs on Xe2 hardware for other reporters, ran test sweeps for pull-request authors, contributed unit tests and a refactor to a community PR ([genai#4139](https://github.com/openvinotoolkit/openvino.genai/pull/4139)), and published a reproducer for a Model Server crash investigation ([model_server#4428](https://github.com/openvinotoolkit/model_server/issues/4428)).
- **Not everything lands.** Some work was closed unmerged or declined, and some I withdrew myself when my analysis was wrong ([genai#4368](https://github.com/openvinotoolkit/openvino.genai/issues/4368)). It stays on the record.

I also publish measurements as open data: two CC-BY-4.0 datasets on [HuggingFace](https://huggingface.co/blairducrayoppat), including a GPU mixture-of-experts offload study and a negative result: an NPU draft model slowed a GPU target below GPU-only speed.

### How I build

I own the architecture, the acceptance criteria and the risk decisions; AI agents write all of the code. The toolchain: **[Claude Code](https://claude.com/claude-code)** (Anthropic) for interactive engineering sessions, a coding fleet running a local model (OpenCode driving a 30B coder model on the Arc 140V, [agentic-setup](https://github.com/blairducrayoppat/agentic-setup-public)) for autonomous runs, and GitHub Copilot for review passes. The standing test gate runs 10,000+ tests at zero failures.
